# Crew Board Implementation Plan (steps 1-2: refs, status, branch, board)

**Goal:** A board with one row per piece of work (a ref), its current state,
whether its branch has reached trunk, and one sentence on where it stands.

**Spec:** `docs/design.md`, section "The board: where each piece of work stands".

## Global Constraints

- Nothing project-specific in the package: refs have no meaning, the trunk is a setting.
- `status` and `branch` are optional on every tool; a crew that never sends them loses nothing.
- The package writes no sentence of its own; the fallback is the latest event's own text.
- The status-bar segment never runs git or reads more than a stat per crew.
- `make check` and `make api-check` stay green.

## Tasks

- [ ] Queue: `STATUS` and `BRANCH` properties, set by create, handoff, park and
      done when given; handoff carries the branch; `read-item` returns both.
- [ ] RPC and MCP: `status` and `branch` on `crew_create`, `crew_handoff`,
      `crew_park`, `crew_done`; the tool text says what a status sentence is.
- [ ] Board: `agent-shell-crew-board`, rows grouped by ref, columns ref, title,
      state, owner, merged, status; `e` rewrites a row's sentence, `RET` opens the item.
- [ ] The health dot's click opens the board.

## Later (not this plan)

- `crew_stage` and recorded stages; project-supplied check stages run in the
  background; health counting stages the human owns.
